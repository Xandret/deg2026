# deg2026 — независимая проверка открытых данных федерального ДЭГ-2026

> **EN:** Independent, reproducible re-verification of Russia's 2026 federal online-voting open data: blockchain journal parsing, running the open-source verifier per chain and diagnosing its failures, cross-checks against official results across 32 regions. Python, parquet, duckdb, static site with a map.

**Сайт:** https://xandret.github.io/deg2026-preview/

**Что это.** Во время выборов в сентябре 2026 года данные дистанционного электронного голосования (ДЭГ) опубликованы открыто. Этот проект проверяет их самостоятельно и так, чтобы любой мог повторить проверку: скачать те же данные, запустить те же скрипты и получить тот же результат.

**Что умеет.**
- Разбирает блокчейн-журнал голосования и раскладывает его в таблицы (parquet, duckdb).
- Перепроверяет криптографию итогов. Агрегацию зашифрованных голосов (ElGamal на эллиптической кривой) и доказательства Chaum–Pedersen проверяет открытый верификатор С. Слотина ([sslotin/elections](https://github.com/sslotin/elections)). Он запускается без изменений, отдельно по каждой цепочке.
- Разбирает случаи, когда проверка не проходит, и находит причины. Например, в реальных блоках транзакция `results` часто стоит раньше частичных расшифровок того же голосования. Верификатор читает строго по порядку и поэтому ошибочно выдаёт INCOMPLETE. Для таких контрактов собираются отдельные дампы, и перепроверка проходит на тех же данных.
- Сверяет итоги с официальными данными избиркома по 32 регионам.
- Выгружает открытые данные и строит статический сайт с картой.

**Как устроено.**
- Python-пакет `deg`, 29 модулей. Запуск одной командой: `setup.cmd`, затем `run.cmd <модуль>`.
- Каждый вывод ссылается на воспроизводимый запрос или скрипт.
- Исходные данные никогда не изменяются, всё производное пересчитывается заново.
- Документация:
  - [архитектура с блок-схемами](docs/ARCHITECTURE.md);
  - [руководство оператора](docs/OPERATOR_GUIDE.md);
  - [журнал решений](docs/decisions.md): 35 записей о том, почему сделано именно так.

**Как сделано.** Предметную область разбирал я: процесс голосования, формат журнала, схему шифрования. Решения тоже мои. Код писал Claude Code по согласованной спецификации, а результат проверяется на данных.

## Быстрый старт (Windows)
1. `setup.cmd` — найдёт Python ≥ 3.11, создаст `.venv`, поставит зависимости. Лог: `logs\setup.log`.
2. `run.cmd <модуль> [аргументы]` — запускает `python -m deg.<модуль>`, пишет лог в `logs\`.

## Раскладка
| Путь | Что лежит | В git? |
|---|---|---|
| `..\` (папка «ДЭГ IT») | исходные дампы, экспорт чата, архивы — **только чтение** | нет |
| `src\deg\` | весь код (пакет `deg`) | да |
| `data\derived\` | вычисленные таблицы (parquet / duckdb) | нет, воспроизводимы |
| `data\external\` | то, что скачали сами (izbirkom, stat.vybory, публичный дамп) | нет |
| `docs\decisions.md` | журнал решений (почему сделано так) | да |
| `docs\tech\` | техническая документация по модулям | да |
| `docs\anomalies\` | карточки аномалий | да |
| `logs\` | логи запусков | нет |

## Правила
- Исходники в «ДЭГ IT» не изменяются никогда. Всё производное — только в `data\`.
- `ChatExport*` и любые секреты (ключи, пароли, номера) — никогда в git и в тексты.
- Время во всех таблицах — **МСК** (UTC+3), если в имени колонки не указано иное (`*_utc`, `*_local`).
- Любой вывод в тексте курсовой должен ссылаться на воспроизводимый запрос/скрипт.
