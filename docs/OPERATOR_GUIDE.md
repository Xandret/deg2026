# Руководство оператора: как повторить всё с нуля

Для того, кто запускает проект: по шагам от сырых копий журнала до сайта. Устройство и обоснования —
`docs/ARCHITECTURE.md`; подробности по каждому модулю — `docs/tech/`.

## 0. Что нужно

| Что | Зачем |
|---|---|
| Windows 10/11, Python 3.11+ | основная машина для тяжёлых шагов |
| 32 ГБ ОЗУ, 8+ ядер | разбор журнала идёт в 12 процессов |
| ≈ 200 ГБ свободного места | копии журнала 2026 (~67 ГБ day1–3), дампы 2024–25 (15 ГБ), база DuckDB (7 ГБ), на время криптопроверки — склеенные цепочки (53 ГБ, потом удаляются) |
| российский IP без VPN | портал наблюдения stat.vybory.gov.ru и izbirkom.ru |
| GnuPG («Simple installer for GnuPG», gnupg.org) | библиотека libgcrypt для криптопроверки |
| Git + аккаунт GitHub | хранение кода и публикация |

## 2. Установка (один раз)

1. Скопировать папку `deg2026` в `ДЭГ IT\` рядом с исходниками.
2. Запустить `setup.cmd`: найдёт Python, создаст `.venv`, поставит зависимости (лог — `logs\setup.log`).
3. Проверить: в конце `logs\setup.log` нет ошибок, `.venv\Scripts\python.exe -c "import duckdb, pandas"` проходит.

Любой модуль: `run.cmd <модуль> [аргументы]`. Вывод дублируется в `logs\<модуль>-<дата>.log` в UTF-8.
В конце `run.cmd` ждёт нажатия клавиши; в своих .cmd-скриптах вызывайте `.venv\Scripts\python.exe -m deg.run …`.

## 3. Полный прогон

Порядок важен: каждый шаг использует результаты предыдущих. «Готово, если» — что проверить в логе.

### 3.1. Журнал → база
```
run.cmd parse_blocks --workers 12
run.cmd build_db
run.cmd validate_slotin
```
Готово, если: `sources` не нашёл разрывов ни в одной из 7 цепочек; `validate_slotin` — 0 расхождений по
бюллетеням, голосам, спискам и итогам (`data\derived\validation_slotin.json`). Разбор возобновляемый (маркеры `_done`).

### 3.2. Прошлые годы (для динамики и криптопроверки 2024–25)
```
run.cmd fetch_yadisk --year 2024
run.cmd fetch_yadisk --year 2025
scripts\legacy_all.cmd
```
Готово, если: `validation_slotin_2024.json`, `…_2025.json` без расхождений.

### 3.3. Портал наблюдения
```
run.cmd portal
```
Нужен российский IP. Каждый ответ кешируется в `data\external\portal\raw\` — повторный запуск бесплатный.
Готово, если: 32 региона, 3 177 голосований, 0 ошибок.

### 3.4. Агрегаты и итоги
```
run.cmd site_data
run.cmd dynamics
run.cmd deg_results
```
Готово, если: явка ДЭГ 90,88 %; 1 044 пары ТИК без непарных; 81 округ.

### 3.5. Протоколы (бумага)
1. В обычном браузере открыть на izbirkom.ru сводную таблицу ОИК (список — `docs\izbirkom_todo.md`),
   DevTools → Network → «Save all as HAR». Файлы — в `data\external\izbirkom\`. Автоматизировать это нельзя:
   у сайта защита от ботов, её не обходим.
2. ```
   run.cmd reconcile_izbirkom
   run.cmd izbirkom_snapshot
   ```
Готово, если: снимок ↔ HAR — 0 расхождений; протоколы ДЭГ ↔ журнал — все совпали. Остаток — в `todo_oik_protocols.csv`.

### 3.6. Криптопроверка
```
run.cmd make_chain_dumps
run.cmd crypto_verify --parallel 4 --workers 2 --years 2024,2025
run.cmd crypto_recheck parse
scripts\recheck_all.cmd
scripts\recheck_2.cmd
run.cmd crypto_recheck summary
```
Готово, если: в `data\derived\crypto_verify\summary.json` подтверждены все итоги (2026 — 5 103, 2024 — 2 103,
2025 — 3 046). «FAILED/INCOMPLETE» в первом проходе — **не вердикт**: почти всегда это порядок записей в блоке
или отброшенный повреждённый голос; перепроверка разбирает каждый случай (docs/tech/08-crypto.md).
После — `data\derived\chain_dumps\shard-*.jsonl.gz` (53 ГБ) можно удалить: `_manifest.json` с контрольными
суммами оставить.

### 3.7. Хронология
```
run.cmd news_scrape --since 2026-09-10 --until 2026-09-24
run.cmd news_scrape --candidates
```
Затем вручную: из `data\derived\news\candidates.csv` отобрать события в `data\news\timeline.json`, для каждого —
сверка с журналом. Перед публикацией сверить статусы источников с реестром иноагентов Минюста
(`data\news\sources.json`, поле `_checked`). Материалы «нежелательных организаций» не используются.

### 3.8. Росстат (один раз в год)
Скачать «Регионы России. Социально-экономические показатели» (Excel-версия, rosstat.gov.ru), распаковать нужные
разделы в `data\external\rosstat\xlsx\`, записать источник и sha256 в `SOURCE.txt`.

### 3.9. Сайт
```
scripts\build_site.cmd
```
Запускает `all_results`, `regions_social`, `monitor`, `export_open_data` и `site\build.py`. Готово, если:
в конце «закрыт от поисковиков (noindex)», в `site\public\` — `index.html`, `404.html`, `robots.txt`, `data\`,
ZIP. Открыть `site\public\index.html` двойным щелчком — это полная версия сайта без интернета.

## 4. Публикация

| Что | Команда | Кому видно |
|---|---|---|
| Показ одному человеку | `scripts\publish_preview.cmd` → https://xandret.github.io/deg2026-preview/ | всем, у кого ссылка; поисковикам — нет |
| Закрытая версия для ОП | папка `site\public` архивом или ссылка на Artifact | кому передали |
| Открытый запуск | `scripts\build_site.cmd --launch --base-url https://АДРЕС/` → выкладка `site\public` на хостинг; зеркало — Actions → «Сайт на GitHub Pages» | всем |

Открытый запуск — только по чек-листу в `docs\tech\10-public-site.md` (согласие ОП, реестр иноагентов, авторство).
Убрать временную ссылку: удалить репозиторий `deg2026-preview` на GitHub.

## 5. Git

- Коммиты и push делает человек на Windows; сообщения коммитов готовятся в `.git\COMMIT_MSG_*`.
- Порядок: `git status` → проверить, что нет `ChatExport`, `*.har`, дампов → `git add -A` →
  `git commit -F .git\COMMIT_MSG_N` → `git push`.
- Что в git не попадает, задано в `.gitignore`: сырые данные, `data\derived`, `data\external`, логи, `.venv`.

## 6. Следующие выборы: чек-лист

**До голосования**
- Получить доступ наблюдателя к узлам; подготовить ноутбук и флешку с `dump-chunked.py` (README в `edg_day3\`).
- `check-observers.py` (рядом с `dump-chunked.py` в репозитории С. Слотина): какие узлы отдают какие цепочки.
- Заранее собрать портал (`run.cmd portal`) — список выборов и голосований.
- Прогнать весь конвейер на данных прошлого года, чтобы убедиться, что формат не поменялся.

**Во время голосования**
- Выгрузка должна идти постоянно: пока `dump-chunked.py` не запущен, новые блоки не пишутся (дыра по времени).
- Разбирать частичную копию (`parse_blocks` + `build_db`) и запускать `run.cmd monitor` раз в час; живой режим
  (каждые 5–10 минут) — в плане развития.
- Сигнал «пауза в цепочке» (R6) почти всегда — сбой выгрузки, а не выборов (урок A-07): сначала проверить источник.

**После**
- Дождаться финальной копии (с расшифровкой и `results` по всем голосованиям).
- Полный прогон (раздел 3), HAR по протоколам, криптопроверка, сайт.

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| В логе «кракозябры» | консоль Windows не в UTF-8 | запускать через `run.cmd` (он включает UTF-8); не использовать `Tee-Object` в PowerShell |
| `crypto_verify`: не найдена libgcrypt | не установлен GnuPG | поставить «Simple installer for GnuPG»; модуль сам найдёт `libgcrypt-20.dll` |
| `portal`: «Портал недоступен» | нет российского IP / включён VPN | выключить VPN, повторить (кеш не потеряется) |
| izbirkom отдаёт «испорченные» числа | защита сайта | только HAR из браузера; `izbirkom_deob` расшифрует |
| rosstat.gov.ru: ошибка сертификата | сертификат Минцифры | скачать файл браузером вручную |
| «Bad CRC-32» при чтении zip | чтение большого архива через сетевую папку | запускать шаг на Windows, не в виртуальной машине |
| Итог «не совпал» в криптопроверке | порядок записей в блоке / отложенная расшифровка / отброшенный голос | `crypto_recheck extract` + `verify` (не записывать в нарушения до перепроверки) |
| Кончается место на диске | склеенные цепочки, логи верификатора | удалить `chain_dumps\*.jsonl.gz`, сжать логи в `.log.gz` (решение №31) |
