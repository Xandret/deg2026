# A-06. Портал наблюдения показывает по одной ТИК на округ Госдумы

- **Тип:** институциональная (удобство наблюдения); понижена 30.09 — см. раздел «Исправление»
- **Вердикт:** подтверждено
## 1. Наблюдение / 2. Данные
- В цепочке 5 103 контракта; при обходе API портала наблюдения (регион → выборы → округ → голосования) видны
  3 177. Невидимые 1 926 контрактов содержат **6 480 523 бюллетеня — 53 %** всех бюллетеней ДЭГ.
- Госдума разбита на контракты по ТИК (Карелия: 19 + 19), портал показывает на округ один contractId (одну ТИК),
  при этом счётчики — окружные, а `issued` превышает число избирателей (суммирует все голосования).
- Интерфейс портала публиковал идентификаторы транзакций (с УИК, выдавшим бюллетень) — т.е. разбивка
  доступна только на уровне отдельных транзакций (со слов А., наблюдателя ОП).
- Электронный протокол ДЭГ по округу на izbirkom **есть** (отдельный узел под ОИК, `isDeg`): в открытом снимке — 66 протоколов
  по 33 ОИК, все совпали с журналом. Вычитание «ОИК − Σ ТИК» нужно только для округов, где этого протокола нет в снимке.

## Исправление 30.09
Прежняя версия утверждала, что на izbirkom ДЭГ отдельно не выделен и проверка думской части ДЭГ доступна только
после ручного сбора протоколов. Это неверно (по внешнему замечанию): итоги каждой ТИК есть в транзакциях `results`, итог по округу —
в электронном протоколе ДЭГ. Остаётся замечание к интерфейсу портала: одна ТИК на странице округа и суммарные счётчики.
## 3–4. Вердикт
Подтверждено как особенность интерфейса, не нарушение. Разбивку ДЭГ по ТИК наблюдатель видит только в журнале;
итог по округу доступен в протоколе. Предложение: показывать на портале все голосования по ТИК с привязкой к округу.
