# A-07. Свердловская область: «обрыв данных по УИК» — артефакт наблюдения

- **Тип:** ложная (артефакт наблюдения)
- **Вердикт:** артефакт наблюдения (реконструкция)
- **Время:** наблюдение 19.09 днём → вопрос 20.09 12:09 МСК

## 1. Наблюдение
На графиках команды по отдельным УИК Свердловской обл. линии «выдано/получено» (условно 73 из 100)
застыли на данных 19.09 и не росли после выгрузки нового дампа 20.09. Вопрос задан в рабочем чате
20.09 12:09; ответ через посредника (14:18) — «ДИТ Москвы обеспечивает голосование на участках… ТЭГи/КЭГи»;
уточнение конструктора ПТК ДЭГ (21.09 23:05): речь об **электронных списках избирателей** ДИТ Москвы.

## 2. Данные
- В итоговых данных у всех 175 свердловских УИК «~73 из ~100» (список 85–120, 65–80 % выдачи к 19.09 12:00)
  бюллетени выдавались и 20.09; ни один не «застыл». У 328 УИК со списком 80–120 после 19.09 13:42 — в среднем +7,9.
- «Застывших» УИК (последняя выдача ≤19.09 при остатке ≥15 % списка) в Свердловской обл. 2,1 % — меньше,
  чем в среднем по стране (2,8 %), и все маленькие (список ≤60).
- Выгрузка day2: с 13:40 19.09 скрипт `dump-chunked.py` падал с «different history» и писал 0 новых блоков;
  тот же сбой на другой флешке в 11:04 (фото в чате). Повторный запуск на той же флешке 20.09 ничего бы не дописал.
- Электронное голосование на участках в 2026 г. — только в Москве (пост. ЦИК № 21/175-9); в Екатеринбурге —
  только электронные списки (ЭСИ), бюллетени бумажные.

## 3. Альтернативные объяснения
- Реальный сбой ДЭГ в регионе — опровергается итоговыми данными.
- Переход избирателей на участки — опровергается: всплеска исключений после «обрывов» нет.

## 4. Вердикт и границы вывода
Наиболее вероятно — артефакт неполной выгрузки у наблюдателей (реконструкция: какой именно дамп и УИК
использовались, точно не установлено). Ценность кейса — методическая: ограничения сбора данных порождают
ложные аномалии, а объяснения по цепочке «наблюдатель → посредник → разработчик» приходят искажёнными и с задержкой.
