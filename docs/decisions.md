# Журнал решений

Формат: дата — решение — почему — какие альтернативы отклонены.

## 2026-09-24 — исходная рамка (итог интервью)

1. **Продукты.** Курсовая + полный технический отчёт (база) + публичный продукт (свой сайт + лонгрид).
   Сначала закрытая страница, затем GitHub Pages под ником; настоящее имя — после согласования с ОП.
2. **Тема курсовой.** «Прозрачность федерального ДЭГ как институт общественного контроля: эмпирический
   анализ выборов 2026 года». Научный руководитель — П.С. Каневский (смена темы с лоббизма).
   Идём к нему с 2–3 готовыми карточками аномалий.
3. **Исследовательский вопрос.** Какие аномалии позволяют выявить открытые данные ДЭГ и где проходят
   пределы такого наблюдения. Рамка — наблюдаемость/проверяемость; технический аудит и электоральная
   статистика — эмпирические главы. Язык: «аномалия», «артефакт»; выводы ограничены тем, что данные
   позволяют утверждать.
4. **План текста.** Гл.1 теория (CM/Rec(2017)5; Эстония, Швейцария, Норвегия; московский ДЭГ —
   институционально, т.к. дампа Москвы в 2026 нет). Гл.2 ДЭГ-2026 как объект наблюдения (архитектура,
   что открыто, как собирали данные — включённое наблюдение, ограничения). Гл.3 каталог аномалий.
5. **Карточка аномалии.** наблюдение → данные → альтернативные объяснения → вердикт
   (подтверждено / объяснено технически / артефакт наблюдения / не проверяемо). 6–8 карточек в
   основной текст, полный каталог — в приложение. Шаблон: `docs/anomalies/_template.md`.
6. **Независимость данных.** Всё считаем сами: свой парсер сырых блоков, свой сбор с izbirkom.
   Таблицы С. Слотина (sslotin/elections) — только для сверки; совпадение подаётся как независимое
   воспроизведение. **Ссылки на команду и литературу обязательны** (отклонено: «без ссылок» —
   академический риск и неверно по существу: дампы собирались скриптом команды).
7. **Люди и секреты.** Участники — по ролям; по именам только публичные лица в публичной роли
   (Д. Кузнецов — конструктор ПТК ДЭГ; О. Артамонов — пред. ТИК ДЭГ; В. Толстогузов; С. Слотин как
   автор публичного репозитория). Секреты из чата не используются нигде; ChatExport только локально.
8. **Сравнение ДЭГ vs бумага** — на уровне одномандатных округов Госдумы / ТИК (итоги ДЭГ есть только
   по контракту, не по УИК).
9. **Свердловская «заморозка»** — описывается как реконструкция (наиболее вероятно: сбой
   `dump-chunked.py` «different history» → 0 новых блоков при повторном запуске на той же флешке;
   объяснение про КЭГ/ТЭГ пришло искажённым через посредника; Д. Кузнецов уточнил: ЭСИ ДИТ Москвы).
10. **Вычисления.** Тяжёлое — нативно в Windows (i9-14900K, 32 ГБ), 12 процессов. Криптопроверка —
    только режим «итоги». Блоки расшифровки — из публичного edg2026.tar со сверкой хешей с нашим day3.
11. **Новости.** Сборщик веб-превью публичных Telegram-каналов (`t.me/s/…`), без авторизации;
    ручной отбор 40–60 событий, баланс: официальные / независимые / СМИ.
12. **Порядок работ.** 1 инфраструктура → 2 парсер+сверка → 3 izbirkom (фон) → 4 метрики и карточки →
    5 криптопроверка → 6 новости (фон) → 7 сайт → 8 текст (.docx по требованиям соцфака).
13. **Режим работы.** Тандем: код пишет Claude, по каждому модулю — техдокументация в `docs/tech/`,
    по которой Алекс разбирается после.

## 2026-09-24 — итоги этапа 2

16. **edg2026.tar для итогов не нужен:** day3 содержит расшифровку и итоги всех 5 103 контрактов.
    Решение №10 уточнено: публичный архив — только для сверки хешей (необязательно).
