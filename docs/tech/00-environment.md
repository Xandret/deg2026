# 00. Окружение и запуск

## Две машины — одна папка
- **Windows (твой ПК)** — где идут тяжёлые вычисления: `setup.cmd`, `run.cmd`. Полные 32 ГБ RAM и все ядра.
- **Linux-VM Claude** — видит ту же папку «ДЭГ IT» (смонтирована), но слабая: 2 CPU, 3,8 ГБ RAM,
  лимит 3 минуты на команду. Там Claude пишет код, тестирует его на маленьких кусках данных и читает
  твои логи из `logs\`.

Поэтому цикл работы такой: Claude пишет модуль и тестирует на сэмпле → ты запускаешь `run.cmd <модуль>`
→ лог падает в `logs\` → Claude его читает и проверяет результат.

## Почему именно так устроены скрипты
- `setup.ps1` написан только ASCII-символами: Windows PowerShell 5.1 читает файлы без BOM в кодировке
  ANSI и ломает кириллицу.
- `run.cmd` выставляет `PYTHONUTF8=1` — иначе Python в Windows пишет в консоль/файлы в cp1251/cp866,
  и русские названия выборов превращаются в кракозябры.
- `PYTHONPATH=src` — пакет `deg` импортируется без установки.
- Пути в коде — через `deg.config` (относительно репозитория), никаких `C:\Users\...` в коде.

## Git — только со стороны Windows
Linux-VM не может удалять файлы в этой папке (так настроен доступ), а git постоянно создаёт и удаляет
lock-файлы (`.git\index.lock`). Поэтому все git-команды выполняются в Windows (Git for Windows).
`setup.ps1` удаляет оставшийся от VM пустой `index.lock` и печатает `git status`.
