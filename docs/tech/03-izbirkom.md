# 03. izbirkom.ru: как устроена выдача и расшифровка (`deg.izbirkom_deob`)

Исследовано 24.09.2026 по HAR, записанному Алексом в обычном браузере
(`data/external/izbirkom/karelia_zaks_segezha.har`, ЗакС Карелии, ТИК «Сегежская (округ №11)»).

## Архитектура сайта (сентябрь 2026)
- SPA на Vue/Quasar (`www.izbirkom.ru/election/<id>/commission/<uuid>/reports/242?type=8`).
- Справочники и дерево комиссий — JSON API `apps.cikrf.ru/service/ik-inp-service-pbcopy/…`:
  `elections/<id>`, `commissionClassifiers?electionsId=<id>[&classifierId=<uuid>]`
  (узлы: type 3 — ОИК, 4 — ТИК, 5 — УИК; флаги protocol1Signed/protocol2Signed, isDegPermitted).
- Перед запросами — антибот-проверка `challenge/get` → `challenge/solve` (JS-задача) → `X-Api-Key`.
  **Её автоматический обход мы не делаем** (решение: данные получает человек в обычном браузере,
  мы работаем с сохранённым HAR).
- Отчёт: `www.izbirkom.ru/reports/242?data={requestParams:{commissionClassifierId, protocolNum}, …}` →
  JSON `{success, html, script}`: HTML с испорченными числами + скрипт-«починщик».

## Расшифровка
Пять типов операций (SET, CUT, MOVE, SWAP, OVERLAY), имена функций случайные в каждом ответе —
см. docstring `deg/izbirkom_deob.py`. Проверка на скриншоте: 12 строк протокола + 7 кандидатов
совпали полностью. Остаётся «ячейка-приманка» вне таблицы (вида `о42.а4мй%`) — отбрасывается.

## Важное наблюдение: протокол ТИК не содержит ДЭГ
Протокол ТИК «Сегежская»: действительных 8 421 = недействительных + ящики − … ; сумма голосов за
кандидатов = 8 421 = только бумажные бюллетени из ящиков. ДЭГ по этому округу (контракт в цепочке):
1 774 выдано, итоги [258, 47, 314, 465, 171, 186, 309] (Σ 1 750). В дереве комиссий ОИК «Сегежский»
имеет одного потомка (ТИК) и флаг `isDegPermitted: true`; отдельного узла «ТИК ДЭГ» нет.
Гипотеза для проверки: протокол ОИК = бумага ТИК + итоги ДЭГ. Проверка: Асмоловский 1 024 + 258 = 1 282.

Как ДЭГ ложится в строки протокола: список = начальный − исключённые; «получено» и «выдано в помещении»
= выданные электронные бюллетени; «в стационарных ящиках» = принятые голоса; 24 выданных, но не
отправленных электронных бюллетеня — это расхождение «выдано − в ящиках» (как незавершённые бюллетени).

**Метод для масштабирования:** ДЭГ(округ) = протокол ОИК − Σ протоколов ТИК; сравнить с суммой
итогов контрактов цепочки, привязанных к округу. Любое ненулевое расхождение — карточка аномалии.

## Госдума (выборы 587813923): структура дерева и протоколы
HAR `karelia_gd_oik20.har`. Дерево: ЦИК России (type 0) → субъект (type 2) → ОИК (type 3,
«Республика Карелия – Карельский», №20, isDegPermitted) → 19 ТИК (type 4). **Отдельного узла ТИК ДЭГ нет.**
19 ТИК = 19 ТИК-контрактов партсписка и 19 одномандатных в блокчейне по Карелии.
`protocolNum`: 1 — одномандатный округ, 2 — федеральный округ (партсписки). Протокол ОИК №20 (партсписки)
подписан 22.09.2026 15:45; расшифрован (71 операция), ЕР 68 821, всего действительных 209 723.
В ПТК «Сводной таблицы» нет (в коде SPA такого отчёта нет) — только протокол по одной комиссии.
План сверки для округа: протокол ОИК + протоколы всех его ТИК по обоим protocolNum → ДЭГ = ОИК − Σ ТИК.

## Автоматическая сверка: `deg.reconcile_izbirkom`
Берёт все HAR из `data/external/izbirkom/`, собирает дерево комиссий и протоколы, для каждой ОИК, у которой
есть протокол ОИК и протоколы всех её ТИК, считает ДЭГ = ОИК − ΣТИК и сравнивает с цепочкой.
Контракты цепочки привязываются к ТИК по номерам УИК (из дерева) + числу позиций бюллетеня; при
неоднозначности сверка не выполняется (ничего не угадываем). Отчёт: `data/derived/reconcile/reconcile_report.json`.
Состояние на 24.09: Карелия ГД ФО — совпадает; Карелия ЗакС Сегежский — совпадает; Белгородская ГД ОМО —
нет протоколов ОИК №79 и №80 и протокола ТИК Алексеевская.
