# 06. Итоги ДЭГ по Госдуме для всех регионов и округов

Модуль: `src/deg/deg_results.py` → `data/derived/deg_results/` (`run.cmd deg_results`, секунды).

## Задача
Портал наблюдения показывает по одному голосованию на округ, а 1 926 из 5 103 голосований (53 % бюллетеней)
не видны вовсе (A-06). Нужно собрать итоги ДЭГ по всем 32 регионам (партии) и 81 одномандатному округу.

## Как устроено
1. **Пары по ТИК.** У каждого контракта ГД берём множество УИК, из которых выдавались бюллетени (хеш
   отсортированного списка). Все 2 088 контрактов ГД (162 видимых + 1 926 невидимых) разбиваются ровно на
   1 044 пары с одинаковым множеством: одна пара = одна ТИК, в ней партсписок (PL) и одномандатник (SM).
   Непарных нет — это и есть проверка метода.
2. **Кто в паре PL, кто SM.** Видимые — по названиям на портале. Невидимые — по размерности бюллетеня:
   у партсписка 10 позиций (порядок партий один на всю страну — проверено по 81 видимому PL). В Вологодской,
   Калининградской и Липецкой областях есть округа с 10 кандидатами — там в 42 парах обе размерности
   равны 10; PL — тот, чьё распределение голосов ближе к видимым PL региона (сумма |Δдолей| ≈ 0,1 против ≈ 1,1).
3. **SM → округ.** Видимый — по порталу. Невидимый — по размерности, если в регионе у округов она разная
   (однозначно). Иначе — по близости распределения голосов к видимому контракту округа
   (`district_how = sim a/b`, a — до выбранного округа, b — до следующего). Это реконструкция.

## Проверки
- Сумма голосов PL по Карелии (все 19 ТИК) = ДЭГ-часть протокола Карельского ОИК (сверка 03-izbirkom).
- Белгородский № 79 и Старооскольский № 80 собраны **реконструкцией** (10 и 12 частей) — и совпали с
  протоколами до сотых по всем кандидатам. Магаданский собран точно — тоже совпал.
- Итог: 39 из 81 округа собраны точно, 42 — реконструкцией; реконструкция будет сверена по протоколам
  ОИК (HAR, собирает Алекс: одна «сводная таблица» ОИК на округ, ДЭГ = ОИК − Σ ТИК).
