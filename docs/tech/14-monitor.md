# ДЭГ-монитор (прототип, `monitor`)

`run.cmd monitor` → `data/derived/monitor/alerts_2026.csv`, `summary_2026.json`, `data/derived/site/monitor.json`.

## Зачем
Во время выборов сбои находились вручную (A-01, A-03, A-07). Прототип проверяет: поймали бы их простые правила,
запущенные по журналу автоматически. Каждое правило использует только то, что уже есть в журнале к моменту сигнала;
окно «вперёд» (≤ 30 мин) — это задержка сигнала.

| Правило | Условие | Задержка | 2026 |
|---|---|---|---:|
| R1 early_finish | finishVoting раньше 20.09 20:15 местного (−30 с допуска) | 0 | 1 214 (A-01 + A-02) |
| R2 stall | регион: ≥ 300 бюллетеней за час, затем 0 за 20 мин; 09–19 местного | 20 мин | 0 |
| R3 accept_gap | регион: за 30 мин ≥ 300 бюллетеней и принято < 50 % | 30 мин | 1 (Магадан, A-03, 00:30 МСК 18.09) |
| R4 uik_100 | УИК со списком ≥ 50: выдан N-й бюллетень из N | 0 | 83 (A-08) |
| R5 rejected_vote | транзакция vote без записи VOTE_ | 0 | 2 (A-10) |
| R6 feed_gap | в цепочке > 5 мин без блоков во время голосования | 5 мин | 0 в полных копиях |

Итог проверки «задним числом»: все три сбоя, видимые в журнале (A-01, A-02, A-03), пойманы; ложных сигналов R1–R3 нет.
Первая версия R2 (по одному голосованию, ≥ 30 бюллетеней за 2 ч → 0 за 30 мин) дала 138 ложных сигналов: утренний пик
сменяется тишиной и в здоровых голосованиях — поэтому правило перенесено на уровень региона.
